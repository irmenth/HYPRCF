# AGENTS.md — 全局约定（Arch Linux 工作机）

跨项目通用约定，适用于本机所有目录；项目细节写在各自项目内的 `AGENTS.md`。

## 1. 环境
- 系统：Arch Linux（zen 内核），Hyprland / Wayland
- 交互 shell：fish；**写 shell 脚本用 bash**
- 编辑器：nvim（`$EDITOR`），图形/项目开发常用 VS Code（`code`）
- 包管理：paru（含 AUR / archlinuxcn 仓库）
- git：`irmenth <napki.re@gmail.com>`，SSH 走 `git@github.com:`

## 2. 工具调用约定
- **权限边界**：本机 sudo 需要密码，不要假设可免密执行。命令需要 root、会改动系统级配置（`/etc`、内核、驱动、启动项、systemd 服务等）、或要**安装/卸载任何包**时，必须先征得用户同意。
- **禁止触碰**：凭证类不读取、不改动；其他敏感、运行时与缓存数据可只读、不改动。
- **命令执行**：读写文件优先用 **agent 专用工具**（`read` / `edit` / `write` 等），不禁止 shell 命令；需要 root 或常驻进程的命令先向用户说明；`git push` 前先让用户看 diff / 确认，提交信息用清晰、叙述式英文；不修改源码的构建、测试和格式化可直接跑；破坏性、不可逆或影响范围大的改动先确认。
  - **读大文件要分段读**：用 `read` 工具（可指定 `offset`/`limit`，有明确的截断提示），不要用 `cat`（一次性输出会被截断，开头内容丢失且无提示）。
  - **临时文件**：一律放系统 `/tmp`，不要写到用户家目录；用完立即删除。
- **语言**：与用户用中文沟通；文件统一 **UTF-8（无 BOM）、LF 行尾**。

## 3. C/C++ 代码格式
- 涉及 C/C++ 文件时，以 `~/.clang-format` 为准；提交前运行 `clang-format -i <files>`。

## 4. 行为原则
1. 改动前先读相关文件，遵循现有风格，不要凭空重写。
2. 小步、可验证地改，改完给出可检查的结果。
3. 可能影响系统/用户数据时，先问用户；对不确定的事实，先联网搜索核实，不要猜测。
4. 任何会影响本文件内容的改动，都要及时同步更新本文件。
5. 不要把配置文件的内容复制进本文件（会造成双份真相）；只引用其路径与用途。
